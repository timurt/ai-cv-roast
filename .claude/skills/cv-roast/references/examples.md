# Recruiter calibration examples

Illustrative CV lines modelled on how a tech recruiter marks up engineering CVs. Use them to calibrate what counts as strong, weak and fixable. ✅ = recruiter praised; ⚠️ = needs a result or number; ❌ = cut or rework.

## Bullets

| Verdict | CV line | Recruiter's note / why |
|---|---|---|
| ✅ | "Cut report generation from 40s to 6s by adding a Redis cache, saving ~$300K a year in compute" | Before→after + money. Keep. |
| ✅ | "Reduced cloud spend by ~$500K a year by replacing a third-party image pipeline with an in-house service" | Money impact. Keep (could name the tech used). |
| ✅ | "Migrated ~3,000 rps and ~200 production services between cloud providers with zero downtime" | Scale + zero downtime. Keep. |
| ✅ | "Mentored two interns, both of whom were hired as junior engineers" | Leadership with an outcome. Keep. |
| ✅ | "Ran A/B tests on the checkout flow that lifted conversion by 12%" | Clear business metric. Keep. |
| ✅ | "Lead the launch of team workspaces, which grew weekly active teams +35% in a quarter" | Strong metric (but "Lead" → "Led"). |
| ✅ | "Raised the bulk-import limit from 5K to 50K rows, unblocking the three largest enterprise customers" | Before→after + named customer impact. |
| ✅ | "Increased pre-merge checks catching bad changes from 120 to 190 a month, reducing on-call pages" | Before→after. |
| ✅ | "Reduced dashboard load time from 12 seconds to 3 seconds" | Before→after. |
| ✅ | "Raised unit-test coverage from 35% to 85%" | Before→after. |
| ✅ | "Raised throughput from 2 to 150 rps by splitting the monolith into services connected through RabbitMQ" | Result + how + tech: the ideal shape. |
| ⚠️ | "Significantly reduced deployment time by introducing a container-based CI pipeline…" | "Significantly" → how much? Give the number. |
| ⚠️ | "The SOC 2 audit helped win more enterprise deals" | "more" → how many? |
| ⚠️ | "Took initiative and published an open-source SDK for the public API" | Weak opener; result? (adoption, stars, customers integrated). |
| ⚠️ | "Facilitated and improved the incident review process… ensuring operational excellence" | Filler phrase; merge with other leadership bullets. |
| ⚠️ | "Led a team of 3 engineers… actively contributing to planning, reviews, and process improvements" | Vague tail; what changed? |
| ⚠️ | "Developed features and improved services using Python, FastAPI, PostgreSQL, Redis, Kafka" | Stack dump with no result. |
| ⚠️ | "Implemented push notification service for 200K users" | Scale given, but result? (delivery rate, engagement, time saved). |
| ⚠️ | "Moved most of the UI components to a shared library" | "most of the" → how many? Result? |
| ⚠️ | "Mentored team members, unblocked them, helped with onboarding, ran standups" | Duties; outcome? |
| ⚠️ | "Optimized database queries over 20,000 records for better performance" | "better performance" → by how much? |
| ⚠️ | "Lead investigation of a critical data-loss incident… [5-line story]" | Good story, too long; cut to result + how in 1–2 lines. |
| ❌ | "Owning the internal permissions service, working towards reducing support tickets" | "-ing" verb, no result. |
| ❌ | "Setting technical direction for the platform team: roadmaps, quarterly planning…" | "-ing" verb, vague. |
| ❌ | "Responsible for the account settings pages" | Duty, not achievement. |
| ❌ | "Contributed to core libraries as well as the search service" | Weak verb, no result. |
| ❌ | "Managing a team of 5 developers…" / "Planning a 6-month migration…" / "Implementing best practices…" / "Communicating with the infrastructure team…" | All "-ing"; past tense + results. |
| ❌ | "Working on a leading online travel booking platform" | Context, not achievement. |
| ❌ | "Utilized a modern tech stack including MySQL, Redis, and Elasticsearch, deployed on Kubernetes" | Stack dump. |
| ❌ | "Built REST API with Flask, SQLAlchemy, Postgres, Celery and Redis" | Tool list, no result. |
| ❌ | "Built authentication service." / "Integrated payment provider." | Duties, no results. |

## Sections and layout

| Verdict | What the CV did | Recruiter's note |
|---|---|---|
| ❌ | Skills as one flat line: "Python, Go, Django, Docker, AWS, PostgreSQL, Redis…" | Split into categories. |
| ❌ | Skills section at the bottom, ungrouped | Move to top, group by category. |
| ❌ | Phone and email at the bottom of the page | Move contacts to the top. |
| ❌ | No summary | Add a summary (mandatory). |
| ❌ | Summary: "7 years of experience across many areas of software development…" | Add concrete achievements and tech. |
| ❌ | Role headers like "SENIOR ENGINEER, ACME CORP; BERLIN — 2021-PRESENT" | Use Company - Role - Dates consistently; add months. |
| ❌ | "Technologies used: TypeScript, React, GraphQL" under each role | Integrate tech into bullets. |
| ❌ | Tech in parentheses after the role title "(Python, Redis, AWS)" | Put tech inside the bullets. |
| ❌ | Italic job titles, dates and degree lines | Italics not recommended. |
| ❌ | Six bullets in one role | Keep 3–4, merge meanings. |
| ❌ | Old certs: a school competition, a decade-old vendor certification, beginner online courses | Keep the most recent only. |
| ❌ | A 6-month QA role with 4 bullets inside a backend CV | Cut or condense. |
| ❌ | "Updated March 3rd, 2024" above the name | Remove. |
| ❌ | Only email in the header, no LinkedIn or location | Add contacts. |
| ❌ | Certifications listed without years | Add year. |
| ❌ | Several short stints (6–14 months) | Explain reasons in the cover letter. |
| ❌ | File named `cv (2) (1).pdf` | Name the CV properly. |
| ❌ | Two-column layout with colour bars, tagline, interest "pills", hobby clubs, 6 languages with levels | Fix format, remove irrelevant info, add Summary and Skills; show interests through an example. |
| ❌ | "Activities: Mentor — teaching bootcamp students backend development" | Show the contribution (how many students, outcome). |
